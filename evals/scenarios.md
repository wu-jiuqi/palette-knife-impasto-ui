# 行为验收场景

这些场景用于检查 Skill 是否遵守职责边界和 image_gen 工作流。验证时应使用隔离目录保存生成结果，不把实验文件写入正式项目。

## 1. 有原型图的按钮组件

输入一张包含主菜单按钮的线框或界面截图，并要求生成刮刀厚涂风格的按钮资源。

应当：

- 先检查图片并说明它承担的是布局、风格还是构图参考。
- 拆出按钮尺寸、文字区域、状态和边缘留白。
- 生成无字按钮底图或明确说明文字需由宿主平台叠加。
- 通过同一风格锚点生成 normal、hover、pressed 状态。

不应当：

- 把整张界面截图当作一个不可拆分的最终按钮资源。
- 把 image_gen 生成的错字当成正式文案。

## 2. 没有原型图的项目界面

输入项目说明、目标平台和已有项目截图，但不提供 UI 原型，要求生成主菜单界面资源。

应当：

- 先读取项目上下文并列出 UI 定位、信息层级和关键假设。
- 先生成一张整体视觉原型，并附文字版布局契约。
- 再使用原型作为参考生成面板、按钮、装饰和图标等独立组件。
- 将原型标记为视觉沟通稿，不把其中的文字和像素坐标当成生产规范。

## 3. 跨平台 UI 资产

输入同一个 UI 需求，目标平台分别为 Godot、Unity、UE 和 HTML。

应当：

- 保持同一视觉资产和风格约束。
- 根据平台调整画布比例、安全区、缩放倍率、透明和切片说明。
- 默认只交付平台中立的图像资源、状态清单和接入说明。

不应当：

- 未经要求生成某个引擎的场景、脚本或网页代码。
- 声称 raster 资源天然具备响应式布局或无障碍能力。

## 4. 刮刀油画 UI 可读性

输入一个小尺寸图标和一组窄按钮，要求保持刮刀厚涂风格。

应当：

- 降低小组件的厚涂密度，保留轮廓和识别孔洞。
- 让文字区域低细节、高对比，并避免均匀颗粒覆盖。
- 生成后检查透明边缘、意外文字和状态差异。

## 5. 失败修订边界

当生成结果出现样式漂移、边缘缺损或透明背景失败时，应进行一次针对性修订，明确修订目标；如果第二次仍不合格，应报告问题和限制，不无限循环生图。


## 6. 组件本体与材质验收

输入搜索栏、下拉栏、Toast 和提示框，要求保持统一刮刀厚涂油画风格但使用不同形状。

应当：

- 每个组件使用独立的生成资产承担本体轮廓。
- 文字区域与油画明暗关系协调，并由运行时叠加文字。
- 交互状态和粒子反馈不破坏组件的刀痕、堆积边缘和透明边缘。
- 在整屏回组后检查，确保没有纯色外框包裹油画资产。

不应当：

- 用纯色矩形、默认圆角卡片或 CSS border 包住油画图。
- 仅改变颜色就把按钮图缩放成搜索栏、下拉栏或提示框。
- 用半透明色块代替可见的颜料体积、刀痕和破损边缘。
