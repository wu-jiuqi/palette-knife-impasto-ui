# 行为验收场景

这些场景检查 Skill 是否遵守共享视觉流程、交付边界和平台适配器协议。验证时使用隔离目录保存生成结果，不把实验文件写入正式项目。

## 1. 有原型图的按钮组件

输入一张包含主菜单按钮的线框或界面截图，并要求生成刮刀厚涂风格的按钮资源。

应当：

- 先检查图片并说明它承担的是布局、风格还是构图参考。
- 建立 component contract，记录尺寸、文字区、Alpha、family、状态和边缘留白。
- 生成无字按钮底图，或明确说明文字由宿主平台叠加。
- 使用同一 style anchor 生成 normal、hover、pressed；focus 可由运行时层实现。

不应当把整张界面截图当成不可拆分的按钮，也不应把 image_gen 的错字当成正式文案。

## 2. 没有原型图的整屏任务

输入项目说明、目标运行时和已有截图，不提供 UI 原型，要求生成主菜单界面资源。

应当先读取上下文，列出定位、信息层级、关键假设和交付模式；先生成 Style Slice 与布局契约，再按优先级生成面板、按钮、装饰和图标，并回组检查。Style Slice 的文字和坐标不能直接当生产规范。

## 3. 默认资产包与运行时实现

同一 UI 需求分别请求 `asset-pack` 和 `runtime-integration`。

- `asset-pack` 只交付平台中立资产、状态清单、manifest、适配说明和共享 QA；不创建网页或引擎项目，并写明运行时未验证。
- `runtime-integration` 读取指定 adapter，在真实运行时验证原生文字、布局、输入、焦点、状态、窗口/视口和加载反馈。
- 未指定运行时时保持平台中立，不擅自生成 H5 或 Godot 代码。

## 4. H5 适配器

要求制作可运行 H5 页面时，应读取 `references/platforms/h5.md`，使用语义 DOM/ARIA、可见键盘焦点、safe-area 与 `dvh/svh`，验证触控目标、响应式尺寸、加载/解码、非预期横向滚动和 reduced-motion。hover 不能是触屏唯一反馈；焦点环可用原生/CSS 层，但不能替代主要油画本体。

## 5. Godot 适配器

要求制作 Godot 4.x UI 时，应读取 `references/platforms/godot.md`，优先使用预置 `Control/Container` 场景和 `Theme/StyleBoxTexture`、`TextureRect/NinePatchRect`，脚本只处理数据、信号和状态。应验证鼠标/键盘/手柄/触控路径、focus/pressed/disabled/selected、弹窗焦点回归、视口安全区、纹理导入和真实运行；没有 Godot 时标记未运行验证。

## 6. Godot Web 与扩展平台

Godot Web 仍走 Godot 适配器，并追加浏览器导出、资源加载和输入限制检查。新平台必须按 `references/platforms/adapter-template.md` 提供节点/资源映射、状态策略、性能预算和证据格式，不能改写共享视觉流程。

## 7. 可读性、材质与颜色模式

输入小尺寸图标、窄按钮、搜索栏、下拉栏、Toast 和提示框。

应当降低小组件纹理密度，保留轮廓和识别孔洞；文字区低细节高对比；语义不同的组件使用相称形状；透明资产真实带 Alpha；RGB 只有在登记为不透明背景/纹理时成立。不得用纯色矩形、默认圆角卡片或 CSS/引擎边框包住并替代油画本体。

## 8. 状态与复用

focus 可以与 selected 同时存在，不要求生成全部笛卡尔积；可在共享图片上叠加运行时状态层。相同视觉家族可复用模板，但不能只改颜色就把按钮拉成搜索栏或提示框。P0 失败阻塞交付，P1/P2 可暂缓并记录 unresolved issue。

## 9. 失败修订边界与工具诚实

当生成结果出现样式漂移、边缘缺损、透明失败或运行时不可用时，最多进行一次针对性修订；仍不合格或缺少 Godot/H5 工具时，报告限制、保留 manifest/提示词和下一步，不编造通过证据。
