# UI 整屏视觉切片规范

整屏任务先确定主题与 UI 组件清单，再用 Style Slice 验证视觉身份与信息层级，随后生成配套生产资产并回组。这个规范适用于游戏、工具、内容产品和其他有完整屏幕构图的 UI；单个图标或小组件可以只做局部契约。切片的形状语法来自项目身份，不强制所有项目使用斜切、撕裂或卡片禁用清单。

## 视觉身份卡

生成前写清：

- 形状和边缘语法：例如手绘边缘、折页、撕裂、非对称框体或其他与项目相符的规则。
- 构图语法：主焦点、次焦点、阅读路径、留白、前中后景和视觉重心。
- 标题系统：字体类别、字重、倾斜/变形、描边/阴影以及与图形的组合关系。
- 色彩角色：背景、主操作、强调、危险/禁用色及大致占比。
- 装饰符号：世界观中可重复的纹章、笔触、贴纸、印章、花瓣或纸张符号。
- 动效语气：入场、悬停、按下和转场的时长、位移感及减少动效时的降级。
- 禁用方向：会让本项目变成普通后台、模板化卡片墙或无意义噪点的做法。

## 两种切片模式

### `asset-pack`

生成一张包含真实层级、标题占位、主操作、次级信息、装饰和状态反馈的静态 Style Slice。它用于判断材质、构图、可读性、文字安全区和缩放假设；不要求创建可点击项目，并在报告中标明运行时未验证。

### `runtime-integration`

将共享资产放进目标 H5 或 Godot 运行时，使用原生文字和实际输入做可点击预览。至少验证主操作、一个次级操作、一个状态反馈、窗口/视口变化、焦点或触控路径。整张生成图加几个热点不能替代真实组件。

## 切片最低内容

- 一张完整屏幕，而不是孤立组件集合。
- 一个明确的主标题或信息锚点和一个主操作。
- 至少一个次级操作或状态反馈。
- 前景、中景、背景三层关系，或能解释其等价层级的构图。
- 一个可辨识的交互/业务状态（例如 focus、pressed、selected、error）。
- `runtime-integration` 时有一个真实可运行的反馈；`asset-pack` 时有对应的静态状态说明。

## 五项验收

生成生产组件前先对定向图评估，状态项检查其实现方案；总分至少 8 分才能进入生产。组件拼装后再次评分，`runtime-integration` 的状态项必须以实际输入反馈为证。每项 0–2 分，任何一项为 0 都要回到身份或构图阶段；不能在组件尚未生成时声称运行时已通过：

1. 3 秒第一眼能否说出这是一个有独立身份的界面？
2. 主焦点、次焦点和阅读路径是否清晰？
3. 标题、文字占位和图形是否形成统一排版系统？
4. 油画媒介是否在主要本体上可见，同时保留文字可读性？
5. `runtime-integration` 的状态反馈是否可感知；`asset-pack` 是否明确记录了状态实现方式？

## 回组检查

生成配套组件并回组后，先复查主题、比例、层级、文字安全区、透明边缘、缩放和状态差异；通过后再补充补间动画、粒子等效果并复验。单个组件好看不能替代整屏验收；平台行为还必须通过对应 adapter 的 QA。
