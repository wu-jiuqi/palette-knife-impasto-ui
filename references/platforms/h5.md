# H5 / DOM 平台适配契约

## 目标与边界

H5 适配器把平台中立的刮刀厚涂 UI 资产接入浏览器运行时。它负责把资产清单、状态矩阵、尺寸与切片契约映射到语义化 DOM、CSS 和少量 JavaScript；它不重新生成资产，也不把油画材质退化为纯色卡片。

共享流程必须先完成：

1. 读取 `component-contract.md` 中的组件记录和状态矩阵。
2. 读取资产真实尺寸、Alpha、建议倍率、bleed、九切或平铺说明。
3. 固定 style anchor；适配阶段只能处理布局、输入、文字、动态数据和状态。
4. 先在一个可点击的垂直切片中验证首屏，再扩展到其他断点。
5. 把实际验证证据和没有验证的项目分别记录，不以“看起来应该可以”代替证据。

平台适配器可以提供实现示例，但默认不代替用户决定项目的框架、构建工具或路由方案。

## 输入与输出

### 必需输入

- 组件 ID、用途、资产路径、建议尺寸和状态。
- 透明 Alpha、safe padding、bleed、九切/平铺/裁切约束。
- 目标断点、设备像素比、输入方式和安全区要求。
- 正式文字、字体、动态数据、本地化和无障碍要求。
- 原型或 style frame 中必须保留的层级与比例关系。

### 适配器输出

- 可追溯的 DOM 结构和资产引用。
- CSS 变量、响应式规则、焦点和状态规则。
- 需要时的最小 JS 行为（状态、对话框、菜单、动态数据）。
- 资产接入表：组件、文件、渲染方式、切片参数、验证状态。
- 验证证据与未验证报告。

## 组件到 DOM 的映射

| 资产/组件 | 推荐语义节点 | 视觉接入 | 约束 |
| --- | --- | --- | --- |
| 页面背景/底图 | `body`、`main` 或语义区块 | `background-image` 或独立 `<img>`；底图不冒充可拉伸面板 | 明确 `background-size`、焦点和裁切；不把文字烘焙进底图 |
| 面板/卡片 | `section`、`aside`、`dialog` | 资产作为面板本体的背景或 `<img>`；可九切时用 `border-image` 或九片方案 | 不再包纯色圆角框；中心区、边缘区和文字安全区须来自契约 |
| 按钮 | 原生 `<button>` | 生成图作为 `background-image` 或同一按钮中的装饰 `<img>`；文案由 DOM 叠加 | 保留键盘、焦点、禁用和 `aria-pressed` 语义；禁止用 `div` 冒充按钮 |
| 搜索栏 | `<label>` + `<input type="search">` | 搜索框资产作为控件容器的材质本体 | `label`、清除/提交行为、窄屏溢出和输入法状态可用 |
| 下拉栏 | `<label>` + 原生 `<select>` 或可访问组合框 | 下拉资产作为外观本体；不隐藏原生语义 | 若自绘列表，必须实现键盘导航、焦点管理和 `aria-expanded` |
| Toast/提示 | `role="status"` 或 `role="alert"` | 独立提示资产；文字由 DOM 注入 | 不以 hover 作为唯一触发；保留读屏顺序和自动消失策略 |
| 图标/徽章 | `<img>`、内联 SVG 或装饰元素 | 透明 Alpha 原图；通过 `alt` 或 `aria-hidden` 说明语义 | 图标有语义时需替代文本；避免把小图标缩放到无法识别 |
| 进度条 | `<progress>` 或带 `role="progressbar"` 的语义结构 | 轨道与填充资产分开或使用契约指定的平铺方式 | 同步 `aria-valuenow/min/max`；不得只靠颜色表达数值 |

生成图承担组件外形、边缘和主要材质；CSS 只能负责尺寸、排版、状态叠加和降级。焦点环、错误提示、加载失败占位等语义状态可以用 CSS 补充，但不得用一层纯色框取代生成图。

## 资产加载与图像规则

- 关键首屏资产使用 `<link rel="preload" as="image">` 或等效策略；非关键装饰允许 `loading="lazy"`。
- `<img>` 必须给出 `width`、`height` 或 `aspect-ratio`，并使用 `decoding="async"`；背景图需要显式尺寸约束，避免布局抖动。
- 需要多倍率时使用 `<picture>`/`srcset`，保留 PNG 作为透明资产的可靠回退；WebP/AVIF 只有在实际浏览器验证后才能宣称支持。
- RGB 图不能称为透明资产；如果它用于不透明背景或纹理叠加，在清单中标记为 `alpha: false` 和实际混合方式。
- 不把 `filter`、大范围均匀噪点或 CSS 渐变当作刮刀厚涂材质；材质本体应来自生成资产。

## 响应式与安全区

- 采用移动优先规则，使用 `clamp()`、相对单位和容器布局；不得用固定坐标把整屏锁死。
- 全屏布局同时考虑 `100dvh`、`100svh` 和 `env(safe-area-inset-*)`；底部操作区为刘海和系统手势预留内边距。
- 每个断点至少验证窄屏、宽屏和一个中间尺寸；断点应来自内容和触控目标，而不是设备名称。
- 交互目标建议至少 `44px × 44px`；若项目有更严格规范，以项目规范为准并记录。
- 必须有溢出断言或人工证据：`document.documentElement.scrollWidth <= window.innerWidth`，横向滚动若是设计的一部分需明确标注。
- 字体、语言和动态数据可能改变宽度；不要把原型中的文字长度当作固定像素约束。

## 状态、动效与可访问性

- 以原生伪类和状态属性驱动：`:hover`、`:active`、`:focus-visible`、`[aria-pressed="true"]`、`[aria-expanded="true"]`、`[disabled]`。
- 触控设备不能依赖 hover；为按下、选中和成功/错误反馈提供可见状态。
- 支持 `prefers-reduced-motion: reduce`，并保证无动画时信息与状态仍然清楚。
- 对话框必须有 `role="dialog"`、`aria-modal="true"`、`aria-labelledby`（必要时 `aria-describedby`），打开时聚焦首个可操作元素，关闭后把焦点还给触发控件。
- 颜色不是唯一状态编码；文字、图标、形状或位置也要传达状态。动态数据由 DOM 文本层负责本地化和读屏。
- 可见焦点不能被厚涂纹理吞掉；允许 CSS 焦点环，但不能改变资产的主要轮廓。

## H5 验证证据

交付时至少记录：

| 检查 | 证据示例 | 结论 |
| --- | --- | --- |
| DOM 语义与键盘 | 浏览器录屏、手动步骤、自动化结果 | 已验证/未验证 |
| 资产加载 | Network 面板、文件尺寸、Alpha 检查 | 已验证/未验证 |
| 视觉状态 | normal/hover/pressed/focus/disabled 截图 | 已验证/未验证 |
| 响应式 | 窄屏、宽屏和中间尺寸截图或 Playwright 结果 | 已验证/未验证 |
| 安全区与溢出 | `scrollWidth` 断言、移动设备截图 | 已验证/未验证 |
| 可访问性 | Lighthouse/axe 或手动读屏记录 | 已验证/未验证 |
| 动效降级 | `prefers-reduced-motion` 测试记录 | 已验证/未验证 |

证据必须包含测试日期、浏览器/版本、视口和资产版本。没有实际执行的项目写入“未验证”，不能写成“支持”。

## 失败与回退

- 资产加载失败：保留尺寸和语义，显示明确的低保真占位，并在报告中记录文件路径和错误。
- 九切不适用：回退到保持比例的整图或分层九片，不用纯色矩形伪造边框。
- 旧浏览器缺少 `dvh`、`prefers-reduced-motion` 或现代图片格式：提供 `vh`、静态状态和 PNG 回退，并标明验证范围。
- 组件无法满足对比度或触控尺寸：先修订资源契约或布局，再通过 CSS 添加语义性焦点/错误提示；不要靠降低纹理来掩盖轮廓问题。
