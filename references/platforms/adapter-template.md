# 通用平台适配器模板

本文件用于把同一套刮刀厚涂 UI 资产接入任意目标运行时。H5/DOM 与 Godot 4.x 的具体规则分别见 h5.md、godot.md；新增平台时复制本模板并补齐该平台的映射，不修改共享资产规则。

- 继承的视觉资产版本/提交：

适配器只改变布局、资源装载、输入、文字、动态数据、安全区和平台语义；它不重新生成图片，也不改变已批准的 style anchor。

## 3. 适配流程

1. **读取资产**：验证路径、尺寸、Alpha、命名和状态，不以文件名推测实际内容。
2. **分类组件**：区分背景、面板、按钮、输入、弹窗、图标、进度条和装饰。
3. **选择原生原语**：优先使用目标平台已有的语义控件和预置布局节点，再接入生成图；避免动态生成整棵界面树。
4. **映射视觉材质**：优先使用平台支持的纹理、九切、平铺或图层能力；不要用纯色框代替油画本体。
5. **映射状态**：normal、hover、pressed、focus、disabled、selected、error 的几何、文字区和输入语义保持一致。
6. **接入文字与动态数据**：文字、计时器、数值、本地化和读屏标签由运行时负责；生成图默认无字。
7. **处理布局**：使用平台的容器、锚点、约束、响应式和安全区能力；记录不可拉伸的区域和最小尺寸。
8. **先验收垂直切片**：至少有一张完整屏幕、一个主操作、一个次级状态反馈和一个真实交互反馈。
9. **扩展到目标矩阵**：每个目标设备、视口和输入方式单独记录，复用资产但不假设行为一致。
10. **交付证据**：区分资源级、编辑器级和运行时级证据；未执行的目标写入未验证报告。

## 5. 布局、文字与无障碍

- 记录平台的逻辑像素、设备像素比、最小触控目标和安全区单位。
- 文字、动态数据、本地化和读屏名称由平台运行时叠加；不要将正式文案烘焙进生成资产。
- 颜色不是唯一状态编码；为选中、错误、禁用和进度提供文字、图标、形状或位置线索。
- 键盘、手柄、触控和鼠标的焦点/按下反馈分别验证；hover 不能是唯一反馈。
- 支持平台的减少动效设置；静态状态应仍能传达层级和结果。
- 组件本体来自生成图；焦点环、错误提示、加载失败占位等语义层可以是平台样式，但不能用它们替换主体材质。

## 6. 资产与资源回退

| 情况 | 首选处理 | 回退处理 | 报告字段 |
| --- | --- | --- | --- |
| 透明纹理不支持 | 平台原生 Alpha 纹理 | 保留尺寸的分层或预合成图 | Alpha 与边缘 |
| 九切不支持 | 平台九切/九片 | 保持比例的整图或分层边框 | 拉伸限制 |
| 现代图片格式不可用 | 已验证的格式 | PNG 或平台原生格式 | 浏览器/运行时范围 |
| 资产加载失败 | 保留语义、尺寸和明确提示 | 低保真占位 | 路径、错误、版本 |
| 动画/悬停受限 | 触发器与静态状态 | pressed/selected 的可见反馈 | 输入设备 |
| 字体/本地化撑破 | 容器和文字区适配 | 可滚动/换行的语义布局 | 语言与视口 |

所有回退都必须保留语义和可操作性；纯色矩形只能作为明确的错误/加载占位，不得交付为油画材质本体。

## 7. 验证证据

每次交付填写：

| 级别 | 必须证明 | 证据 |
| --- | --- | --- |
| 资源级 | 路径、尺寸、Alpha、切片参数和状态文件正确 | 资源检查、导入面板或脚本输出 |
| 编辑器/构建级 | 场景、主题、布局和构建产物可加载 | 编辑器截图、构建日志、资源清单 |
| 运行时级 | 交互、焦点、状态、文字和响应式表现成立 | 可复现步骤、录屏/截图、自动化报告 |
| 目标平台级 | 每个设备/浏览器/导出目标的关键路径成立 | 目标环境日志和截图 |
| 可访问性级 | 键盘/读屏/对比度/触控目标满足项目规范 | axe/Lighthouse、手动记录或项目检查表 |
| 性能级 | 纹理、帧时间、内存和加载预算有测量 | profiler、Network 或构建指标 |

证据写明：测试日期、平台版本、设备/视口、输入方式、资产提交、测试步骤和结果。编辑器预览、单张静态图或“理论上支持”不能代替运行时证据。

## 9. 新平台扩展准入

新平台的参考文件至少回答：

1. 平台中哪个原生节点/资源承载组件语义？
2. 如何接入透明纹理、九切、平铺和整图？
3. 状态、焦点、输入、无障碍和文字由什么机制负责？
4. 如何处理响应式、安全区、DPI 和动态本地化？
5. 如何在桌面、移动、Web 或主机等目标间复用同一资产？
6. 哪些能力需要降级，如何保留语义？
7. 哪些证据能证明资源级、运行时级和目标平台级行为？
8. 哪些项目仍未验证，如何写出可执行的下一步？

若这些问题无法回答，适配器只能交付为“资源接入草案”，不能宣称平台支持已完成。
