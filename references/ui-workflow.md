# UI 工作流

## 1. 判断输入模式

先判断用户是否提供了线框、截图、Style Frame、参考图或现有 UI 资源。

- 有原型：原型优先约束布局、信息层级、区域关系和需要保留的比例。
- 无原型：项目资料和用户要求优先；只在必要时作最小假设，并在交付中列出。
- 多张图片：为每张图标记角色，例如布局参考、色卡、风格参考、主体参考或编辑目标。不要因“参考”二字自动复制全部内容。

## 2. 有原型图

1. 使用 `view_image` 检查所有本地图，确认实际可见内容和尺寸；会话图片按宿主支持的引用机制处理。
2. 写出简短的屏幕结构：画布比例、背景、面板、主要操作、信息区、装饰区、文字占位和安全区。
3. 建立组件清单，区分应生成的图像资产和应由平台实现的文字、布局、逻辑、动画及动态数据。
4. 为每个组件记录状态矩阵，只生成当前需求需要的状态。常见状态为 `normal / hover / pressed / focus / disabled / selected / error`。
5. 为组件制定提示词，使用原型作为构图或比例参考；原型中的文字只提示长度和位置，默认不烘焙到新图。
6. 按逻辑资产分别调用 `image_gen`，不要把整张界面拼贴图当成可拆分生产资源。

## 3. 无原型图的 fallback

1. 读取项目说明、场景、截图、已有资源、目标平台、分辨率、响应式要求和交互方式。
2. 判断 UI 的视觉身份、信息优先级、主要操作、情绪关键词、材料和需要避免的网页化元素。
3. 先调用 `image_gen` 生成一张整体视觉原型（Style Frame），用来沟通屏幕气氛、层级和组件关系。
4. 同时输出文字版布局契约，说明区域、锚点、信息层级、假设和不应依赖原型图文字的内容。原型是视觉方向，不是像素级布局或正式文案。
5. 使用原型图和布局契约建立组件清单、状态矩阵及导出规格，再逐项调用 `image_gen` 生成可交付资产。

## 4. 统一生成规则

- 首次生成前固定 style anchor：媒介、笔触方向、材质、主次色关系、边缘处理和细节密度。
- 有本地参考图时先 `view_image`，再使用 `referenced_image_paths`；仅有会话图片时使用覆盖全部所需图片的最小 `num_last_images_to_include`。两者不可同时传。
- 提示词中的 Image 1、Image 2 等必须与实际传入顺序一致。
- 无参考图的新资产只传提示词；透明组件要求真实 Alpha，不使用绿幕或棋盘格假透明。
- 不同组件默认分开调用；用户明确需要图集或状态表时，才将同一逻辑资产组合输出。

## 5. 检查与修订

逐项检查用途、轮廓、材质、颜色、状态差异、透明边缘、意外文字、留白和与原型的关键关系。发现问题时只改动导致失败的约束，最多进行一次定向修订。第二次仍失败时报告限制和可执行提示词，不无限生图。
