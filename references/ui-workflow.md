# UI 工作流

这是平台中立的共享流程。目标运行时的布局、输入、导入和性能检查放到 `references/platforms/`，不要把 H5 或某个引擎的实现细节混进视觉核心。

## 1. 判断输入模式

先判断用户提供的是线框、截图、Style Frame、参考图、现有 UI 资源还是编辑目标，并提取：

- `delivery_mode`：默认 `asset-pack`；用户要求接入、实现或可运行时才用 `runtime-integration`。
- `runtime`、版本、输入方式、画布/响应式范围、导出目标和项目约束。
- 每张图片的角色：布局、色卡、风格、主体或编辑目标；不要因“参考”二字自动复制全部内容。

## 2. 先确定主题，再建立组件清单

1. 先写本次主题与视觉身份：内容、情绪、媒介、主次色、形状、装饰符号、刀痕方向和细节密度。用户授权自定时直接确定；已有项目约束明确时沿用其主题，不添加确认关卡。
2. 有本地图时用 `view_image` 检查实际内容和尺寸，并登记参考角色。旧项目资源默认仅作参考，不自动成为本次生产资产。
3. 按内容与操作路径写出屏幕结构：画布比例、前中后景、主要操作、信息区、装饰区、文字和安全区；据此列出所需 UI 组件。
4. 为每项记录 `component_id / theme_id / family / semantic_role / priority / required_states`、比例、透明要求和文字安全区，区分要生成的本体与平台负责的文字、逻辑、焦点和状态层。清单必须先于整屏定向图和生产组件的生成。

## 3. 有原型图

1. 原型优先约束布局、信息层级、区域关系和需要保持的比例，不把生成文字或像素坐标当成生产规范。
2. 判断原型中的文字只是位置/长度提示，除非用户明确要求，否则不烘焙进生产图片。
3. 以第 2 步的主题和清单为基础，整屏任务先按 `game-ui-vertical-slice.md` 检查构图；单个小资产可直接进入契约和生成。
4. 按 P0/P1/P2 实际调用 `image_gen` 生成本次配套组件：P0 独立生成或明确状态变体，本次生成的同一几何家族可共享模板，但要记录最小尺寸和裁切限制。

## 4. 没有原型图的 fallback

1. 读取项目说明、场景、截图、已有资源、目标平台、分辨率、响应式要求和交互方式。
2. 先完成第 2 步的主题与 UI 组件清单，输出信息优先级、主要操作、假设和需要避免的方向。
3. 用 `image_gen` 生成 Style Slice，细化布局契约、状态矩阵和导出规格，再依据清单实际生成配套组件；不能只生成主视觉后沿用其他主题的控件。
4. Style Slice 是视觉方向和回组参考，不是正式文案、像素级坐标或响应式实现的唯一依据。

## 5. 统一生成规则

- 每项视觉组件必须能追溯到本次主题的生成结果；本次生成的同家族组件可以共享。用户明确指定使用已有资产时登记来源与适配检查；不得自行用旧项目成品替代本次生成，更不能只改旧组件名称或颜色来冒充新主题资产。
- 透明前景要求真实 Alpha；独立不透明背景、底图和纹理可用 RGB，但要在契约中登记。
- 有本地参考图时先 `view_image`，再使用 `referenced_image_paths`；仅有会话图片时使用覆盖全部所需图片的最小 `num_last_images_to_include`；两者不可同时传。
- 提示词中的 Image 1、Image 2 等必须与实际传入顺序一致。
- 正式文字、长文案、动态数据默认由运行时叠加；图中文字是 artwork content 时单独记录和验收。
- 使用同一 style anchor 维持跨平台视觉一致性；平台适配只改变实现和测量，不随意改变媒介身份。

## 6. 检查与修订

检查用途、轮廓、材质、颜色、状态差异、透明边缘、意外文字、留白、最小尺寸和与原型的关键关系。失败时只改动导致失败的约束，默认最多做一次定向修订；第二次仍失败就交付限制、未解决问题和可执行提示词。

## 7. 拼装与运行时路由

组件生成检查完成后再拼装。`asset-pack` 做静态回组；`runtime-integration` 读取对应平台 adapter，将配套组件、原生文字和实际交互接入目标运行时：

- H5：DOM 语义、ARIA、焦点、safe-area、dvh/svh、响应式、加载和触控。
- Godot：预置 Control/Container 场景、Theme/StyleBoxTexture、TextureRect/NinePatchRect、键盘/手柄/触控、视口安全区、纹理导入和真实运行。
- 其他平台：复制 `adapter-template.md`，只补平台差异和证据要求。

先验证主题一致性、文字、比例、输入与状态；P0 不通过时回到身份/组件阶段，不进入效果润色。

## 8. 拼装通过后补充补间动画、粒子与其他效果

- 从已拼装的界面确定入场、悬停、按下、转场补间的目标、触发方式、时长与缓动，再补与主题相符的环境粒子。
- 登记粒子所需贴图；若需要新的厚涂贴图，沿用本次 style anchor 调用 `image_gen` 生成并检查，不能把旧项目粒子默认带入。
- 效果不得遮挡文字、接管点击/焦点或改变状态语义；控制粒子密度、活动范围与性能预算，保留减少动效和关闭粒子的路径。
- `asset-pack` 交付效果方案和所需资产，不创建运行时工程；`runtime-integration` 实现并检查。效果不适用或用户要求静态时写明原因。
- 最后执行共享 QA 与平台 QA，分别留存静态拼装、动效/粒子开启及降级证据。资产缺失不得靠特效掩盖。
