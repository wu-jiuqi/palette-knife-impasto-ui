# UI 组件资产契约

每个组件在生成前后都应有一条简短记录。未提供的信息作最小假设，并标记为假设。

```text
Component ID:
Purpose:
Target platform:
Asset type:
Canvas ratio / suggested size:
State:
Reference images and roles:
Color and material:
Transparent background:
Safe padding / bleed:
Text and data treatment:
Nine-slice / tiling / cropping:
Invariants:
Exclusions:
```

## 资产类型

- **独立组件**：按钮、图标、徽章、游标、装饰。保持完整轮廓并留出安全边距。
- **面板和边框**：优先生成可拆分的框体或纹理，说明中心区、边缘区和是否适合九切。
- **底图和场景 UI**：明确画布比例、视觉焦点和文字/动态数据留白；不要把底图误交付为可拉伸面板。
- **状态图集**：只在用户需要时输出；为每个格子记录状态和尺寸，保持同一视角、轮廓和材质锚点。

## 透明、文字与可读性

- 透明组件必须是真实 Alpha，不能带绿幕、棋盘格或意外背景色。
- 正式文字、数字、计时器、长文案和本地化内容默认不烘焙进图像。
- 需要文字时生成干净的可叠字区域，并由目标平台负责字体、排版、焦点和语言切换。
- 小图标应优先保证轮廓、方向、孔洞和识别比例，再增加厚涂细节。

## 尺寸、边缘和切片

- 生成前明确目标画布比例、建议像素尺寸、1x/2x/3x 倍率或其他缩放约束；工具实际返回尺寸需核验后才能报告。
- 需要缩放的面板要保留可延展的边缘和低变化中心区，说明九切或平铺建议；不要声称生成图天然无缝。
- 给阴影、刀痕和外轮廓留下 bleed，避免切片或裁切时削掉关键结构。
- 组件命名应包含功能、状态和版本，例如 `menu_button_normal_v01`；不要覆盖旧版资源。

## 状态矩阵

状态差异必须在提示词中写清楚，并保持几何关系不变：

| 状态 | 视觉提示 | 不应改变 |
| --- | --- | --- |
| normal | 基准材质、基准明暗 | 轮廓、内边距、文字区 |
| hover | 局部高光、轻微色温或刀痕强调 | 尺寸、语义、可读性 |
| pressed | 压低的明暗、内陷或颜料受压痕迹 | 位置、轮廓、图标方向 |
| focus | 清晰可识别的焦点边缘或对比环 | 主要材质和文字区 |
| disabled | 降低对比度或饱和度 | 仍需可辨识、不可伪装成缺失 |
| selected/error | 明确但受控的强调色或装饰 | 基础结构和平台叠字区 |
